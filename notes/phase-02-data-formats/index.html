Data Formats

In Phase 1 we learned how a message travels. Now we open the parcel and look at what’s inside: JSON, XML, XSD, XPath, XSLT and CSV. This is the heart of OIC’s mapper.

1Why data formats?

The bank formWhen you open a bank account, you don’t write a free-style letter. You fill a form: Name here, Date of birth there, PAN in this box. Because everyone fills the same form, the bank can read thousands of them quickly. A data format is a form that computers agree on.

The body of a request (Phase 1, chapter 7) is just text. But the sender and receiver must agree on how that text is arranged, or the receiver can’t find the name, the salary or the date. The two most common arrangements are JSON and XML.

2JSON basics

A contact cardYour phone stores a contact as labels with values: Name → Ravi, Phone → 98xxxx, City → Pune. JSON (JavaScript Object Notation) is exactly that: a list of labels (keys) and their values, inside curly brackets.

The 6 kinds of values

TypeExampleThink of it as
String"Ravi Kumar"Text. Always in double quotes.
Number101, 55000.50Amounts and counts. No quotes.
Booleantrue / falseA yes/no tick box. No quotes.
NullnullThe box exists, but it’s empty.
Object{ "city": "Pune" }A form inside a form.
Array["SQL", "OIC"]A list, in square brackets.
The 4 rules that break JSON. ① Keys and text in double quotes (not single). ② A comma between pairs, but no comma after the last one. ③ No comments. ④ Every { and [ must be closed.

Watch out: "101" (with quotes) is text, but 101 is a number. Systems care about this difference.

3Nested JSON: objects & arrays

Boxes inside boxesA courier box can hold smaller boxes. JSON works the same: a value can itself be an object (a smaller form) or an array (a list of things). That’s how one JSON can describe a whole employee, or a whole list of employees.

To point at one value, follow the tree with dots: address.city → Pune. Arrays count from zero: skills[0] → SQL, skills[1] → OIC.

A list of employees is simply an array of objects: {"employees": [ {…Ravi…}, {…Priya…} ]}. When an API returns many records, this is what you’ll see.

4XML basics

Labelled jarsImagine a kitchen where every jar has a label on the lid and on the bottom: <sugar> … </sugar>. XML (eXtensible Markup Language) wraps every value between an opening tag and a closing tag. Older enterprise systems, SOAP services and Oracle Fusion use it a lot, and OIC uses it inside.

Element or attribute?

Both hold data. An attribute sits inside the opening tag (id="101") and is best for small labels like IDs or codes. An element (<name>…</name>) is best for the main data, and only elements can hold other elements.

“Well-formed” XML follows 5 rules. ① Exactly one root element. ② Every opening tag has a closing tag (or is self-closing, like <photo/>). ③ Tags close in the right order: inner first. ④ Tag names are case-sensitive: <name> ≠ <Name>. ⑤ Attribute values in quotes, and special characters escaped: & → &amp;, < → &lt;.

5Namespaces

Two Ravis in one classWhen two students are both called Ravi, the teacher says “Ravi Kumar” and “Ravi Sharma”. The surname tells them apart. A namespace is a surname for XML tags, so two tags with the same name but different meanings don’t get confused.

xmlns:hr="http://company.com/hr" declares the namespace: the prefix hr stands for that long name. The address looks like a web link, but it’s only a unique name: nothing is downloaded from it.

Why you must care in OIC. The mapper shows prefixes like ns0:, nsmpr0: everywhere. And an XPath without the right namespace finds nothing, which is one of the most common “why is my value empty?” problems. You’ll see this live in chapter 12.

Neither is “better”. As an integration developer you must be comfortable reading both, because you’ll receive one and send the other all the time.

7XSD: the rule book

The blank form vs the filled formThe bank prints a blank form that says: Name (text, required), Age (number, required), Nominee (optional), Phone (up to 3). Your filled form must follow it. XSD (XML Schema Definition) is the blank form; the XML is the filled one.
XSD wordPlain meaning
simple typeA single value, no children: xs:string, xs:integer, xs:decimal, xs:date, xs:boolean
complexTypeA box that holds other boxes (children) or attributes
sequenceThe children must appear in this order
minOccursAt least how many times. 0 = optional, 1 = required (the default)
maxOccursAt most how many times. unbounded = as many as you like (a list)
use="required"The attribute must be there
Well-formed vs valid. Well-formed = the grammar is correct (tags closed, one root). Valid = well-formed and it follows the XSD. <salary>fifty thousand</salary> is well-formed, but not valid, because the XSD says salary is a decimal number.

In OIC, schemas are what draw the trees you see in the mapper. When you give OIC a sample JSON, it quietly creates a schema from it; when you connect a SOAP service, its WSDL brings its XSD with it.

8XPath: finding a value

Folder pathsOn your laptop, /Users/prabir/Documents/resume.pdf tells you exactly where a file is. XPath is a path to a value inside XML, written the same way with slashes.
XPathMeansResult (our XML)
/employees/employee[1]/nameFull path from the rootRavi Kumar
//name// = search anywhereRavi Kumar, Priya Sharma
//employee[@id='102']/dept@ = attribute; [ ] = filterHR
//employee[salary > 50000]/nameFilter by a valueRavi Kumar
count(//employee)How many2
sum(//salary)Add them up103000

Other handy functions: concat(a, ' ', b) joins text, substring(), contains(), string-length(), normalize-space() (trims spaces), upper-case(), and current-dateTime().

In OIC, every field you drag in the mapper is really an XPath, something like $GetEmployee/nsmpr0:response/ns1:name. The $ part is a variable holding a message, and the prefixes are namespaces. Switch Conditions, Assign and Filter all use XPath too.

9XSLT: reshaping XML

A recipeYou have ingredients (the input XML) and a recipe card (the XSLT). Follow the recipe and you get a new dish (the output XML). XSLT (eXtensible Stylesheet Language Transformations) is a recipe for turning one XML shape into another. It uses XPath to pick the ingredients.
InstructionDoes
templateWhere the recipe starts
value-ofCopy one value
for-eachRepeat for every item
ifOnly when a test is true
choose / when / otherwiseIf… else if… else
variableRemember a value to reuse
In OIC, when you drag lines in the mapper, OIC is writing XSLT for you behind the scenes. Open the mapper’s code view and you’ll see xsl:for-each, xsl:value-of and xsl:choose, exactly like this. Knowing XSLT lets you fix what drag-and-drop can’t.

10JSON ↔ XML in OIC

The interpreter’s notebookAn interpreter listens in Hindi, writes notes in her own shorthand, and speaks in English. OIC receives JSON, converts it to XML inside, maps it with XSLT, and converts it back to JSON if needed.

11CSV & delimited files

A spreadsheet saved as plain textOpen Excel, save as .csv, then open it in Notepad: each row is one line, and the columns are separated by commas. CSV (Comma-Separated Values) is the most common format for file-based integrations, like a bank sending a daily payments file over SFTP.

Delimiter

The separator character: comma ,, pipe |, tab, or semicolon. Agree on it first.

Header row

The first line with column names. Some files have none, so check.

Quotes

Wrap a value in "…" when it contains the delimiter.

Fixed-length

Older files use positions instead: characters 1–5 = id, 6–30 = name.

In OIC, you describe a CSV file’s columns once (OIC creates a special schema for it, called an NXSD), and then the Stage File action reads the file into XML that you can map like anything else.

xmllint --noout --schema employees.xsd employees.xml

4 · Run XPath

xmllint --xpath "string(/employees/employee[1]/name)" employees.xml   Ravi Kumar
xmllint --xpath "//name/text()" employees.xml                    Ravi Kumar  Priya Sharma
xmllint --xpath "string(//employee[@id='102']/dept)" employees.xml  HR
xmllint --xpath "count(//employee)" employees.xml                  2
xmllint --xpath "sum(//salary)" employees.xml                      103000

5 · See the namespace trap

xmllint --xpath "//name/text()" ns-employee.xml
XPath set is empty                                 ← the tag is really hr:name
xmllint --xpath "//*[local-name()='name']/text()" ns-employee.xml
Ravi Kumar

14Common mistakes

  1. 1
    Trailing comma in JSONThe last pair must not end with a comma. The whole request fails with a 400.
  2. 2
    Number sent as text"salary": "55000" when the API expects 55000.
  3. 3
    Wrong case in XML<Name> and <name> are different tags.
  4. 4
    Unescaped &“Johnson & Sons” must be written Johnson &amp; Sons inside XML.
  5. 5
    Namespace mismatchThe XPath looks right but returns nothing, because the namespace is different.
  6. 6
    Single item vs listA sample JSON with only one array item can make OIC treat a list as one value.
  7. 7
    Required field missingThe XSD says minOccurs="1", but the mapping left it empty.

15Self-check

Answer in your head first, then tap to check.

1. What are the 6 kinds of values in JSON?

String, number, boolean, null, object, array.

2. What’s wrong with {"id": 101, "name": "Ravi",}?

The comma after the last pair (a trailing comma).

3. In {"skills": ["SQL", "OIC"]}, what is skills[1]?

OIC. JSON arrays count from 0.

4. Name 3 rules of well-formed XML.

One root; every tag closed; correct nesting order; case-sensitive names; quoted attributes and escaped special characters.

5. Well-formed vs valid?

Well-formed = correct grammar. Valid = well-formed and follows the XSD.

6. What does maxOccurs="unbounded" mean?

The element can repeat any number of times: it’s a list.

7. What does //employee[@id='102']/dept return?

HR. @ means attribute, and [ ] filters.

8. Does XPath count from 0 or 1?

From 1. (JSON arrays count from 0.)

9. Your XPath is correct but returns nothing. What do you check first?

The namespace.

10. What is the OIC mapper really writing behind the scenes?

XSLT, with XPath to pick each value.

All of it, in one sentence

Systems send data as JSON or XML (or CSV files); an XSD is the rule book that says what valid data looks like; XPath points to a value; and XSLT reshapes one structure into another, which is exactly what OIC’s mapper does.
