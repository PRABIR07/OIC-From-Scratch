APIs

1What is an API?

The menu and the waiterIn Phase 1’s restaurant, you never walk into the kitchen. You read the menu (what you can order, and how), and the waiter carries your order in and the food out. An API (Application Programming Interface) is the menu plus the waiter for a software system.

A contract

The API promises: “send me this, and I’ll answer with that.” Both sides rely on it.

A safe door

Other systems get exactly what they need, never the whole database.

Everywhere

Swiggy shows Google Maps, pays via Razorpay, sends an SMS: all APIs.

In integration, almost every connection OIC makes is an API call. And every integration you build in OIC becomes an API that others can call.

2REST: the most common style

A libraryA library is full of things (books, members, loans), and you do a small set of actions on them: look up, borrow, renew, return. REST (REpresentational State Transfer) designs an API the same way: things are resources with addresses (URLs), and the HTTP methods are the actions.

The 5 REST habits

① Resources are nouns. /employees, not /getEmployees. The method is the verb.

② Methods are the actions. GET reads, POST creates, PUT replaces, PATCH updates part, DELETE removes (Phase 1).

③ Stateless. Like the forgetful waiter from Phase 1: every request carries everything needed, including who you are.

④ Usually JSON. REST can carry XML too, but JSON is the norm.

⑤ Status codes tell the result. 200, 201, 400, 401, 404, 500… (Phase 1).

3Endpoints & resources

Shelves and books“Fiction shelf” is a collection; “the third book on it” is one item; “its index page” lives inside that book. REST addresses work the same: collections, single items, and things nested inside items. One address + one method is called an endpoint.
EndpointMeans
GET /employeesList all employees (a collection)
GET /employees?dept=HRList, filtered by a query parameter
GET /employees/101One employee (path parameter)
POST /employeesCreate a new employee in the collection
PATCH /employees/101Update part of employee 101
DELETE /employees/101Remove employee 101
GET /employees/101/payslipsA nested resource: 101’s payslips

Notice: the same address /employees/101 does three different things, depending on the method. That’s why “right URL, wrong method” gives a 405.

API documentation is the menu card. It lists every endpoint, its parameters, a sample request and response, and the possible errors. Many APIs publish it in a standard format called OpenAPI (also known as Swagger). Always read it first.

4SOAP: the formal letter

A government letterA REST call is like a quick WhatsApp message. A SOAP call is like an official letter: a fixed envelope, a cover sheet, the actual matter inside, and strict rules about format. SOAP (Simple Object Access Protocol) always sends an XML “envelope”, usually with POST, to one address. Older enterprise systems, banks and Oracle Fusion still use it a lot.

Everything from Phase 2 shows up here: it’s XML, it uses namespaces (soap:, m:), and the shape is defined by an XSD. In chapter 13 you’ll send this exact request to a real public SOAP service.

5WSDL: the SOAP menu card

The full menu with recipesA REST API’s documentation is often a web page. A SOAP service ships a strict, machine-readable menu: the WSDL (Web Services Description Language, said “wiz-dull”). It lists every operation, exactly what to send, what comes back, and where to send it. Tools like OIC and Postman read it automatically.
In OIC, you give the SOAP adapter the WSDL URL (or upload the file), and it shows you a dropdown of operations. Pick one, and the request and response trees appear in the mapper, built from the WSDL’s types.

6REST vs SOAP

RESTSOAP
Feels likeA WhatsApp messageAn official letter
What it isA style (a set of habits)A strict protocol
Data formatUsually JSON (XML allowed)Always XML, in an envelope
MethodsGET, POST, PUT, PATCH, DELETEAlmost always POST
AddressesOne URL per resourceUsually one URL; the operation is in the body
ContractOpenAPI docs (optional)WSDL (required)
ErrorsHTTP status codesA soap:Fault in the body (usually with HTTP 500)
Where you’ll see itModern apps, most new APIs, Fusion RESTBanks, older ERPs, Fusion SOAP services

Interview line: “REST is a lightweight style built on HTTP methods and resources, usually with JSON. SOAP is a strict XML protocol with a WSDL contract.” OIC handles both, and often converts one into the other.

7Who are you? Authentication vs authorization

The office buildingAt the gate, security checks your ID card: who are you? That’s authentication. Inside, your card opens the 3rd floor but not the server room: what are you allowed to do? That’s authorization. Fail the first, get a 401. Fail the second, get a 403 (the hotel story from Phase 1).

Because REST is stateless, the API doesn’t remember you. Every request carries its proof, almost always in the Authorization header. There are four common kinds of proof:

Basic Auth

Username + password on every call.

API key

One long secret code for your app.

OAuth 2.0

Get a short-lived token first, then use it.

JWT

A token format that carries signed details.

8Basic Auth & API keys

Basic Auth: showing your ID every time

Join the username and password with a colon, encode it with Base64, and send it in a header:

So Basic Auth is only safe over HTTPS (the sealed envelope from Phase 1). Try it yourself: echo dXNlcjpwYXNzd2Q= | base64 --decode gives back user:passwd. It’s simple, which is why many internal and Oracle Fusion integrations use it with a dedicated integration user.

API key: the gym membership card

The gym gives you a card with a code. You show it at the door; they don’t ask your name. An API key is a long secret string the provider gives your app, sent in a header (often x-api-key) or sometimes as a query parameter. It identifies the app, not a person, and must be kept secret like a password.

9OAuth 2.0: the hotel key card

Reception and the room cardAt a hotel, you show your ID at reception once. They give you a key card that opens only your room, and only until checkout. You use the card, not your ID, at every door. OAuth 2.0 works the same: prove who you are once to an authorization server, get a short-lived access token, then use that token on every API call.
OAuth wordPlain meaning
Client IDYour app’s username at the auth server
Client secretYour app’s password. Never share it.
Token URLThe reception desk’s address
Access tokenThe key card: sent as Authorization: Bearer …
ScopeWhich doors the card opens (read only, HR data, …)
ExpiryCheckout time. After it, the card stops working.

The other common flow: authorization code

When you click “Sign in with Google” on a website, you’re sent to Google, you log in there and click Allow, and the website gets a token without ever seeing your Google password. That’s the authorization code flow: used when a real person must give permission. Client credentials is for system-to-system, with no person involved.

Why OAuth beats Basic Auth: the password travels once instead of on every call, tokens expire on their own, scopes limit damage, and access can be cancelled without changing any password.

10JWT: the boarding pass

An airline boarding passYour boarding pass has your name, seat and flight printed on it, and a barcode the airline signed. The gate staff trust it without calling the check-in counter, because the signature can’t be faked. A JWT (JSON Web Token, said “jot”) is a token that carries its own details plus a signature. Many OAuth access tokens are JWTs.

exp is the expiry time, written as seconds since 1 Jan 1970 (called epoch time). This one, 1767142800, means 31 Dec 2025, 01:00 UTC: an hour after iat (“issued at”). Paste any JWT into jwt.io to read it, or decode it with the command in chapter 13.

Never put secrets in a JWT’s payload, because anyone holding the token can read it. And treat the whole token like a password: whoever has it can use it until it expires.

11Pagination, filtering & rate limits

Google search resultsGoogle found a million results, but shows you 10 per page, with “Next” at the bottom. Sending a million results at once would be slow for everyone. APIs do the same: they return data in pages, and you ask for the next page until there’s none left.
StyleLooks likeSeen in
Offset + limit?offset=200&limit=100Oracle Fusion
Page number?page=3&size=50Many APIs
Cursor / next link"next": "…?cursor=abc"Large modern APIs

Filtering and sorting also use query parameters: ?dept=HR, ?sort=name. Oracle Fusion uses ?q=, for example ?q=PersonNumber=101. Filter on the server: it’s far faster than downloading everything and filtering in OIC.

Rate limits: one plate at a time

A buffet has a rule: one plate per visit, so everyone gets food. APIs set limits too, like 60 requests per hour. Cross it and you get 429 Too Many Requests. Many APIs tell you where you stand in headers such as x-ratelimit-limit and x-ratelimit-remaining, and sometimes Retry-After says how many seconds to wait.

12Postman: your API workbench

A test kitchenBefore a dish goes on the menu, the chef tries it in a test kitchen. Postman is a free app where you try an API by hand, before you build anything in OIC. Pick a method, paste a URL, add headers and a body, click Send.

Collection

A folder of saved requests. Share it with your team as one file.

Environment

A set of values for one place: Test, Production, Practice.

Variable

{{baseUrl}} in double curly brackets is replaced by the environment’s value.

Authorization tab

Pick Basic, Bearer, API key or OAuth 2.0, and Postman builds the header.

Switch the environment from Test to Production and every request in the collection now points at the new server, without editing a single URL. OIC connections work the same way: the URL and credentials live in the connection, not in each integration.

14Where this shows up in OIC

IdeaWhere you meet it in OIC
REST APIsREST adapter: Connection URL in the connection; resource, method, parameters and sample JSON in the integration
SOAP & WSDLSOAP adapter: give it the WSDL, pick an operation from the list
AuthenticationThe connection’s security policy: Basic Authentication, OAuth Client Credentials, API key, and more. The credentials live there, never in the mapping.
OAuth tokensOIC fetches and refreshes the token for you once the policy is set
Your own APIA REST trigger turns your integration into an API with its own endpoint, which other systems call, and OIC protects it with its own security
PaginationA While loop that keeps calling until hasMore is false (Phase 7)
Rate limits & errorsFault handling and retries for 429 and 5xx (Phase 7)
PostmanTest the target API first, then test your finished OIC integration’s endpoint the same way
Golden habit: before building any integration, make the call work in Postman first. If it fails in Postman, it will fail in OIC too, and Postman shows the problem much faster.

15Common mistakes

  1. 1
    Credentials in the URL or the codeKeep them in the OIC connection or a Postman environment, never typed into requests or shared screenshots.
  2. 2
    Thinking Base64 is encryptionIt’s just encoding. Basic Auth needs HTTPS.
  3. 3
    Expired tokenA call that worked an hour ago now gives 401. Get a fresh token.
  4. 4
    Reading only page 1The API returned 100 of 2,500 records and nobody noticed. Check hasMore.
  5. 5
    Missing Content-TypeSending JSON without Content-Type: application/json, or SOAP without text/xml, often gives a 400 or 415.
  6. 6
    Ignoring the SOAP FaultSOAP errors hide inside the body. Read the faultstring.
  7. 7
    Skipping the docsMost “mystery” errors are answered in the API documentation’s example request.

16Self-check

Answer in your head first, then tap to check.

1. Explain an API in one sentence.

A menu plus a waiter: a defined way for one system to ask another for data or actions, without seeing its insides.

2. Why is /getEmployees a poor REST endpoint?

Resources should be nouns; the HTTP method is the verb. Use GET /employees.

3. Name the parts of a SOAP envelope.

Envelope, optional Header, required Body; errors come back as a Fault inside the Body.

4. What does a WSDL contain?

Types (XSD), messages, operations (portType), binding (how) and service (where).

5. Authentication vs authorization?

Who are you (fail → 401) vs what are you allowed to do (fail → 403).

6. Is Basic Auth encrypted?

No. It’s only Base64-encoded, so it must be sent over HTTPS.

7. In OAuth client credentials, what do you exchange for a token?

The client ID and client secret, at the token URL.

8. What are a JWT’s three parts?

Header, payload, signature, separated by dots.

9. An API returns "hasMore": true. What do you do?

Call again with the next offset, and repeat until hasMore is false.

10. What should you do before building an integration in OIC?

Make the API call work in Postman first.

All of it, in one sentence

An API is a system’s menu and waiter: REST uses resources and HTTP methods with JSON, SOAP sends XML envelopes described by a WSDL, every call proves who it is with Basic Auth, an API key or an OAuth token (often a JWT), big results come in pages within rate limits, and Postman is where you try it all before OIC.
