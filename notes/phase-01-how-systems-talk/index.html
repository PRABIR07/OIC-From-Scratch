1Client & server

The restaurantYou order a masala dosa. The order goes to the kitchen, the chef cooks it, and the dosa comes back to your table. You never see the kitchen. You only need to know how to order correctly.

Client

Whoever starts by asking. Chrome, the Swiggy app, Postman, or a whole system like Oracle HCM.

Server

A program that waits, listens and answers. Web server, application server, database server.

Three rules

① The client always starts. The kitchen never sends food you didn't order.

② One server, many clients. One kitchen serves many tables at once.

③ Roles, not machines. The chef is a server to you, but a client when he orders from his vegetable supplier.

2DNS: the contact list

Your phoneYou tap “Mom” and the phone dials her number. You never remember the number itself. Computers only understand numbers (IP addresses), so DNS turns a name like google.com into an IP address.
In OIC: a wrong host name fails at this step with UnknownHostException. It means “couldn’t find this name”, not “the API is broken”.

3URLs: where to go

A postal addressFlat 12, Rose Apartments, Mumbai. The letter reaches the right city, then the right building, then the exact flat. A URL narrows things down the same way. URL = Uniform Resource Locator.
https://api.company.com:443/hcm/v1/employees/101?dept=finance&status=active#details

Protocol · the travel rules. https = sealed envelope.

Domain (host) · which server. The city. DNS turns it into an IP.

Port · which door. Hidden when it’s the default.

Path · which resource. The building. v1 = version.

Path parameter · one exact item. The flat number.

Query parameters · filters, like Swiggy. ? starts, & joins.

Fragment · a spot on the page. Never sent to the server.

Path = who

/employees/101 · one exact employee. Usually required.

Query = which ones, how

/employees?dept=finance · filters the list. Usually optional.

URL encoding: URLs can’t hold spaces, so Ravi Kumar travels as Ravi%20Kumar (or Ravi+Kumar in a query). An & inside a value becomes %26.

4Ports: bank counters

A bankOne building, many counters: deposits, loans, new accounts. One server runs many services, and the port says which counter (door) to go to.
443HTTPS
80HTTP
53DNS
22SFTP (files)
1521Oracle DB

google.com is the same as google.com:443: browsers hide the default port. A firewall is a security guard that can close a door, so a server can be found but not reached.

5HTTP methods: what to do

Your contact listYou view, add, rewrite, fix one detail, or delete a contact. The URL says where; the method says what.
MethodDoesContacts exampleSafe to repeat?
GETReadView Ravi’s contactYes · changes nothing
POSTCreateSave a new contactNo · makes duplicates
PUTReplace wholeRewrite the whole cardYes
PATCHUpdate partFix only the numberNot always
DELETERemoveDelete the contactYes

Together these are CRUD: Create, Read, Update, Delete.

PUT vs PATCH · Ravi moves to Mumbai

Lift button vs “Place order” button. Pressing a lift button 5 times still brings one lift (GET, PUT, DELETE). Pressing a badly built “Place order” button 5 times makes 5 orders (POST). “Same result if repeated” is called idempotent. Be careful when retrying a POST in OIC.

6Status codes: what happened

The waiter comes back“Here’s your food!” · “We’ve moved next door.” · “Not on the menu.” · “The kitchen has a problem.” Every reply starts with a number, and the first digit is the family.

2xx · success

200 OK · 201 Created · 204 No Content

3xx · go elsewhere

301 moved for good · 302 moved for now · new address in the Location header

4xx · your mistake

400 bad request · 401 who are you? · 403 not allowed · 404 not found · 405 wrong method · 409 conflict · 429 too many

5xx · server’s problem

500 broke inside · 502 bad answer from next server · 503 busy · 504 next server too slow

401 vs 403 · the hotel

Golden rule. 4xx: fix your request; sending it again unchanged won’t help. 5xx: their side; often temporary, a retry later may work. Exception: 429 means wait, then retry slowly.

7Headers & body: the parcel

A courier parcelThe label on the outside says who it’s for and what’s inside. The box holds the real thing. Headers are the label; the body is the contents.
HeaderWhat it says
Content-TypeThe format I’m sending, e.g. application/json
AcceptThe format I want back
AuthorizationProof of who I am (password or token). Missing or wrong → 401
LocationWhere something moved (with a 3xx)

GET and DELETE usually have no body (you’re only asking). POST, PUT and PATCH carry one.

8HTTP vs HTTPS

HTTP = postcard

Anyone on the way can read it. Port 80.

HTTPS = sealed envelope

Encrypted with TLS; only the two ends can read it. Port 443.

A certificate is the server’s ID card, signed by a trusted authority, like an Aadhaar card a bank accepts because the government issued it. The padlock in your browser means it was checked and trusted.

9One request, start to finish

Every topic above is one step in this journey. It happens every time you open a website or OIC calls a system.

  1. 1
    Read the URLProtocol, domain, port, path. → URLs
  2. 2
    DNS lookupDomain name → IP address. → DNS
  3. 3
    Knock on the portConnect to door 443. → Ports
  4. 4
    TLS handshakeCheck the certificate, seal the envelope. → HTTPS
  5. 5
    Send the requestMethod + path + headers + (body). → Methods, headers & body
  6. 6
    Get the responseStatus code + headers + body. → Status codes

10Try it yourself

Open Terminal (Mac: Cmd + Space, type Terminal). jsonplaceholder.typicode.com is a free practice API: it answers like a real server but saves nothing.

See every request in Chrome

Cmd + Option + I → Network tab → Cmd + R → click a row
Each row = one request + one response. Look for URL, Method, Status Code.

Step 2 · DNS lookup

nslookup jsonplaceholder.typicode.com
Address: … ← the IP. "Non-authoritative" = answered from a resolver's cache. Normal.

Step 3 · Is the door open?

nc -vz jsonplaceholder.typicode.com 443
Connection to jsonplaceholder.typicode.com port 443 [tcp/https] succeeded!
-v = tell me what happened · -z = just knock, send nothing

Steps 4–6 · The whole conversation

curl -v https://jsonplaceholder.typicode.com/posts/1
*  lines = connection + TLS handshake + certificate
>  lines = your request (method, path, headers)
<  lines = the response (HTTP/2 200, headers) … then the JSON body

Create something (POST)

curl -i -X POST https://jsonplaceholder.typicode.com/posts \
  -H "Content-Type: application/json" \
  -d '{"title":"Learning OIC","userId":1}'
HTTP/2 201  … { "title": "Learning OIC", "userId": 1, "id": 101 }

See a 404

curl -i https://jsonplaceholder.typicode.com/posts/9999
HTTP/2 404  … {}   ← "not on the menu"

12A connection fails: check in order

Interview favourite

  1. 1
    Is the name found?nslookup · fails with UnknownHostException → wrong or private host name.
  2. 2
    Is the door open?nc -vz host port · fails or times out → firewall; ask the network team.
  3. 3
    Is the envelope sealed?TLS · certificate not trusted → upload the server’s certificate into OIC.
  4. 4
    What did the server say?401 credentials · 403 roles · 404 URI or ID · 405 method · 500 their team · 503/504 retry later.
Only after all four pass do you start suspecting your integration itself.

13Self-check

Answer in your head first, then tap to check.

1. Who starts the conversation, the client or the server?

The client. A server only answers when asked.

2. In OIC, which one makes OIC the server: trigger or invoke?

Trigger. OIC receives the request. With an invoke, OIC is the client.

3. What does DNS do?

It turns a name like google.com into an IP address, like a phone’s contact list.

4. In /orders/5001?status=shipped, what’s the path parameter and the query parameter?

Path parameter: 5001. Query parameter: status=shipped.

5. What’s the default port for HTTPS?

443. Browsers hide it, so google.com = google.com:443.

6. You send only one field with PUT. What can happen?

The other fields can be wiped, or the API rejects it. Use PATCH to change one field.

7. Why is retrying a POST risky?

POST creates something new each time, so a retry can create duplicates.

8. 401 or 403: “I know who you are, but you’re not allowed”?

403 Forbidden, a permission problem. 401 means “who are you?”.

9. You get a 503. Fix your request, or retry later?

Retry later. 5xx is the server’s side and often temporary.

10. Which header carries your proof of identity?

Authorization.

All of it, in one sentence

A client uses a URL to find the server, over a sealed HTTPS envelope, with a method saying what to do, headers as the label and a body as the contents. The server replies with a status code, headers and a body.

That sentence is exactly what every OIC integration does. Next up, Phase 2: what’s inside the body, with JSON, XML, XSD, XPath and XSLT.
