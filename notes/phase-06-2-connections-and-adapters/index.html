Connections & adapters

Phase 6 · OIC Basics. Before an integration can talk to any system, OIC needs to know how to talk to it and where it is. That’s what adapters and connections are. In this part you understand them properly and create your first two connections, click by click.

1Adapter vs connection

WhatsApp and a chat with RaviWhatsApp knows how to send messages, photos and voice notes to anyone. But to actually message Ravi, you need Ravi’s chat: his number, saved in your phone. WhatsApp is the adapter (the know-how). Ravi’s chat is the connection (one specific person, with his details).
AdapterConnection
IsBuilt-in know-how for one kind of systemAn adapter + one real system’s address and login
Made byOracle (it comes with OIC)You
ExampleREST adapter, FTP adapter, Oracle ERP Cloud adapter“Payroll_API”, “Supplier_SFTP”, “Acme_ERP_DEV”
How manyFixed listAs many as you need, one per system

And here’s the important part: one connection is reused by many integrations. If ten integrations call the payroll API, they all use the same Payroll_API connection. When payroll’s password changes, you update it once.

2Kinds of adapters

OIC has a long list of adapters (see Design → Adapters). They fall into a few families. You don’t need to learn them all: learn the families, and the few you’ll use most.

FamilyExamplesKnows how to…
🌐 TechnologyREST, SOAP, FTP, FileSpeak a general technology. Works with any system that uses it (Phases 1–3)
🗄️ DatabaseOracle Autonomous Transaction Processing (ATP), Oracle Database, MySQL, SQL ServerRun SQL, call procedures, poll tables (Phase 4)
🏢 Oracle applicationsOracle ERP Cloud, Oracle HCM Cloud, Oracle CX, E-Business Suite, NetSuiteShow the app’s business objects (Invoice, Worker, Supplier) as a list, so you don’t look up URLs
☁️ Other SaaS appsSalesforce, ServiceNow, Workday, SAP, Shopify, SlackThe same for non-Oracle apps
📬 Messaging & otherOracle Advanced Queuing, Kafka, email…Queues, streams and more
Which to choose? If a specific adapter exists for the application, prefer it: it shows the app’s objects and handles its security for you. If not, the app almost certainly has a REST or SOAP API, and the REST or SOAP adapter works with anything. That’s why we start with REST.

3Roles: trigger, invoke, or both

The front door and the gateYour house has a front door where visitors come in, and you go out through the gate to visit others. A connection’s role says which way it’s used: are others coming in to OIC through it, or is OIC going out?
RoleMeansExample
TriggerOthers use it to start your integrationA REST endpoint the mobile app calls
InvokeYour integration uses it to call outCalling the payroll API
Trigger and InvokeEither way, in different integrationsAn ERP connection that listens for events and also creates invoices

The role screen only offers what the adapter supports. If you create a connection as Invoke and later try to use it as a trigger, OIC shows an error. Choose the role on purpose.

4The five parts of a connection

Every connection, for any adapter, is filled in the same five areas. Learn this shape once, and every connection screen will feel familiar.

That’s exactly like saving a contact: who (name), where (number or address), how to get in (the gate code), which road, and a test call to check the number works.

5Build your first invoke connection, step by step

Follow this with OIC open next to the notes. Do one step, check that your screen matches “✓ You’ll see”, then go to the next. Don’t skip ahead.

What we’re building, and whyWe’ll create a project (a folder for our work), and inside it a connection called JSONPlaceholder_API. It is OIC’s way out: later, an integration will use it to call the free practice API you used in Phase 3, https://jsonplaceholder.typicode.com. That API needs no login, so it’s the easiest possible first connection.

Part A · Open OIC

  1. 1
    Open the right websiteOpen your OIC address (the Service console link of your instance, which you bookmarked). Make sure the top bar shows the ORACLE logo and your instance name, like learn-oic-… (Dev).
    ✓ You’ll see: the “Ready to get started?” home page.
    ✗ If you see a “Cloud” logo and menus like Compute, Storage and Networking, you’re in the Oracle Cloud Console, not OIC. Go to ☰ → Developer Services → Integration → click your instance → Service console.
  2. 2
    Open the menuClick the ☰ icon to the left of the ORACLE logo.
    ✓ You’ll see: a menu with Home, Projects, Design, Observability, Settings.

Part B · Create a project (your folder)

  1. 3
    Go to ProjectsIn the menu, click Projects.
    ✓ You’ll see: a Projects page, empty at first.
  2. 4
    Start a new projectClick Add (top right), then choose Create.
    ✓ You’ll see: a panel asking for the project details.
  3. 5
    Name itIn Name, type My First Project. Leave every other box as it is. Click Create.
    ✓ You’ll see: your project page, with sections called Integrations, Connections, Lookups and JavaScript libraries. All are empty.
Why a project? A project keeps everything for one solution together: its integrations, connections and lookups. Oracle Integration 3 is built around projects, and in Part 6.3 we’ll build our first integration inside this same project. (You can also create connections outside projects, from Design → Connections → Create. Both open the same panel.)

Part C · Create the connection

  1. 6
    Add a connectionOn the project page, find the Connections section and click Add. (When the project already has connections, this is a + button instead.)
    ✓ You’ll see: a Create connection panel with a long list of adapters and a search box.
  2. 7
    Pick the adapterIn the search box, type REST. Click REST in the results.
    Why REST? Because JSONPlaceholder is a REST API (Phase 3.1), so we use the REST “plug”.
    ✓ You’ll see: a form asking for Name, Identifier and Role.
  3. 8
    NameType JSONPlaceholder_API.
    Why: name connections after the system they reach, so anyone can recognise it later.
  4. 9
    IdentifierDon’t type anything: it fills itself as JSONPLACEHOLDER_API (capitals, no spaces). It’s the connection’s permanent ID that OIC uses behind the scenes.
  5. 10
    RoleChoose Invoke.
    Why: OIC will call out to this API. (Trigger would mean the API calls OIC, which isn’t what we want.)
  6. 11
    Description (optional)Type Free practice REST API. Leave Share with other projects switched off.
  7. 12
    Create itClick Create.
    ✓ You’ll see: the connection’s settings page, with sections for Properties, Security and Access type, and Test and Save buttons at the top. A progress percentage shows how complete it is.

Part D · Fill in the settings

  1. 13
    Connection TypeChoose REST API Base URL.
    Why: we’ll give OIC the API’s main address. (The other option, an OpenAPI URL, is for APIs that publish a description file.)
  2. 14
    Connection URLType exactly https://jsonplaceholder.typicode.com
    Careful: no slash at the end, and no path like /users. Only the base address goes here; each integration adds its own path later.
  3. 15
    TLS Version and other optional boxesLeave them empty.
  4. 16
    Security policyChoose No Security Policy.
    Why: JSONPlaceholder is public and asks for no username, password or token. (A real company API would need one: Part 6.2, chapter 7.)
  5. 17
    Access typeKeep Public gateway selected.
    Why: the API is on the public internet, so OIC can reach it directly.

Part E · Test and save

  1. 18
    TestClick Test at the top of the page.
    ✓ You’ll see: a green message that the connection was tested successfully, and the progress shows 100%.
    ✗ If it fails, check the URL letter by letter (a common typo is “jsonplaceholdr”), and that there’s no slash at the end. Fix it and click Test again.
  2. 19
    SaveClick Save.
  3. 20
    Go backClick the Back arrow (top left).
    ✓ You’ll see: your project page, with JSONPlaceholder_API listed under Connections.

Notice what you did not enter: any path like /users/1. The connection holds only the base URL, the part that’s the same for every call. The specific path (/users/{id}) is chosen later, inside each integration. That’s what lets one connection serve many integrations.

6Build your first trigger connection, step by step

The way INYour house has a gate you go out through, and a front door visitors come in through. JSONPlaceholder_API was the gate (OIC goes out). Now we build the front door: REST_Trigger, which lets other systems call your integrations and start them.
JSONPlaceholder_APIREST_Trigger

  3. 3

    Why: this connection is for calls coming in to OIC.

    ✓ You’ll see: a settings page with fewer boxes than last time, and no Connection URL. That’s normal for a trigger.

    Why: anyone calling your integration must prove who they are, either with a username and password (Basic) or a token (OAuth), as you learned in Part 3.3. This option accepts either.

Checkpoint. Your project now has a way in (REST_Trigger) and a way out (JSONPlaceholder_API), both at 100%. That’s everything Part 6.3 needs to build your first integration: something calls OIC through REST_Trigger, and OIC fetches data through JSONPlaceholder_API.

7Security policies: Part 3.3, now as a drop-down

Remember all the ways an API checks who you are? In an invoke connection, they appear as one drop-down called Security policy. Pick the one the other system’s documentation asks for, and fill in its boxes. OIC then adds the right header to every call for you.

Security policyYou fill inOIC sends (Part 3.3)
No Security PolicyNothingNo credentials: public APIs only
Basic AuthenticationUsername, passwordAuthorization: Basic …
API Key Based AuthenticationThe key, and where it goes (header or query)x-api-key: … or ?appid=…
OAuth Client CredentialsToken URL, client ID, client secret, scopeGets a token, caches it, sends Authorization: Bearer …
OAuth Authorization Code CredentialsSame, plus a one-time Provide Consent loginBearer token, refreshed for you
OAuth Custom Two/Three Legged FlowEach token request described by handFor APIs that don’t follow the standard exactly
AWS, OCI signatures, JWT assertions…Keys and certificatesSigned requests for specific clouds
Two things beginners miss. ① For OAuth Authorization Code (and the custom three-legged flow), filling the boxes isn’t enough: you must click Provide Consent and log in once, or the connection never works. ② For Basic Authentication, the Test button only checks it can reach the URL; it does not check the password. A wrong password shows up later, as a 401 inside a run.

8Access type: which road does OIC take?

Three kinds of addressesA shop on the main road: any courier can reach it. A flat inside a gated society: the courier needs a private gate pass. A house inside a military area: only someone who lives inside can collect the parcel at the gate and carry it in. OIC’s three access types are those three cases.
Access typeUse when the system is…Example
Public gatewayOn the public internet (most SaaS apps and public APIs)JSONPlaceholder, Salesforce, Oracle Fusion
Private endpointInside your company’s private network in Oracle Cloud (a VCN)A database in your OCI network with no public address
Connectivity agentInside your company’s own data centre (on-premises), behind a firewallAn old payroll database in the office server room

For everything in Phase 6, choose Public gateway. The other two need setup by an admin, and you’ll meet them on real projects.

9The connectivity agent, simply explained

Big companies still run many systems in their own server rooms. Their firewall blocks anything coming in from the internet, so OIC in the cloud can’t reach them directly. The solution is clever:

  1. 1
    InstallAn admin downloads the agent from Design → Agents and installs it on a small server inside the company network.
  2. 2
    It calls outThe agent connects outward to OIC over HTTPS and keeps asking “any work for me?”. Outgoing traffic is normally allowed, so no firewall hole is needed.
  3. 3
    It carries the workWhen an integration needs the on-premises database, OIC hands the request to the agent, the agent runs it inside the network, and sends the answer back.

Agents belong to an agent group. In a connection, you choose Connectivity agent as the access type and pick the group. Real projects install two agents in one group, on two servers, so integrations keep working if one server goes down. You can check agents are alive in Observability → Agents.

10Test, save, and connection status

SituationWhat it means / what to do
Test is green, 100%OIC could reach the system with these settings. Save it.
Test fails: host not foundTypo in the URL, or the system isn’t on the public internet (wrong access type). Remember DNS from Phase 1.
Test fails: 401The credentials are wrong (for policies that are actually checked during the test)
Test fails: certificate / SSL errorThe system’s HTTPS certificate isn’t trusted. An admin uploads it in Settings → Certificates
Status not 100%Some required boxes are empty, or Test hasn’t passed. Integrations can’t use it properly yet.

Changing a connection changes every integration that uses it, as soon as you save. That’s powerful (fix a password once) and dangerous (break ten integrations at once). Before editing, look at which integrations use it: OIC won’t let you delete a connection that’s still in use.

DEV vs PROD: keep the same connection name and identifier in every instance, but different URLs and passwords. In DEV, Payroll_API points to payroll’s test system; in PROD, to the real one. When you move an integration from DEV to PROD, it finds a connection with the same identifier, and you only fill in PROD’s details.

11Other adapters at a glance

Every adapter follows the same five parts. Only the “where” and “how to log in” boxes change. Here’s what the common ones ask for.

Adapter② Where③ Login
SOAPThe WSDL URL, the file from Part 3.2Basic, WS-Security Username Password Token, or none
FTPHost, port, and whether it’s SFTP (secure)Username + password, or an SSH key
Oracle ATP (database)The database wallet file and service name (Part 4)A database username and password
Oracle ERP Cloud / HCM CloudYour Oracle Fusion host addressAn integration user (Basic) or OAuth
Salesforce, ServiceNow…The instance addressUsually OAuth with Provide Consent

The Oracle application adapters are a big help: instead of looking up Fusion’s REST URLs (Part 3.4), the integration wizard lists the business objects (Invoice, Supplier, Worker) and their operations for you to pick. You’ll use them in Phase 8.

12Good habits from day one

Name by system, not by integration

Payroll_API, not Connection_for_my_salary_flow. Many integrations will share it.

One connection per system

Don’t create five copies of the same API. Reuse one.

A dedicated integration user

Never your personal login. When you leave the company, integrations shouldn’t break.

Least privilege

The connection’s user should only have the roles the integrations need (Part 3.3).

Write a description

Who owns the other system, and who to call when it’s down.

Test after every change

Click Test before Save, every time.

14Common mistakes

  1. 1
    Putting the full path in the connection URL…typicode.com/users/1. Only the base URL goes in the connection.
  2. 2
    A slash at the end of the URLLeave it off: …typicode.com, not …typicode.com/.
  3. 3
    Wrong roleAn Invoke-only connection can’t be used as a trigger.
  4. 4
    Forgetting Provide ConsentOAuth Authorization Code connections stay broken until you do it.
  5. 5
    Trusting a green Test for Basic AuthThe password isn’t checked until a real call.
  6. 6
    Using your personal loginIt expires or leaves with you. Use an integration user.
  7. 7
    Public gateway for an on-premises systemIt can’t reach inside the firewall. Use the connectivity agent.

15Words you learned

WordMeaning in one line
AdapterA ready-made “translator” that lets OIC talk to one type of system (REST, FTP, Oracle ERP…), so you don’t write code
ConnectionAn adapter + one real system’s address and login, reusable by many integrations
Role (of a connection)Trigger (way in), Invoke (way out), or both
Connection URLThe base address of the system, without a path
Security policyHow OIC proves who it is (Basic, API key, OAuth…)
Provide ConsentThe one-time login some OAuth connections need
Access typeThe road: public gateway, private endpoint, connectivity agent
Connectivity agentA small program inside a company network that carries OIC’s work to on-premises systems
Agent groupA set of agents (usually two) that share the work
Business objectAn app’s thing, like Invoice or Worker, listed by application adapters

16Self-check

Answer in your head first, then tap to check.

1. Ten integrations call the same payroll API. How many connections do you need?

One, shared by all ten.

2. A mobile app will call your integration. Trigger or invoke connection?

Trigger: it’s the way in.

3. Why doesn’t a REST trigger connection have a URL box?

OIC creates each integration’s address itself, when the integration is activated.

4. Name the five parts of a connection.

Identity, properties (where), security (login), access type (road), and test & save.

5. A partner API needs a token from a token URL with a client ID and secret. Which policy?

OAuth Client Credentials.

6. The Test button is green for a Basic Authentication connection. Is the password definitely right?

No. The test only checks the URL can be reached; a wrong password shows up later as a 401.

7. The database is in the company’s own server room. Which access type?

Connectivity agent.

8. Why does the agent not need a hole in the firewall?

It connects outward to OIC and asks for work; nothing comes in from outside.

All of it, in one sentence

An adapter is Oracle’s know-how for a kind of system; a connection is that adapter plus one system’s address, security policy and access type, created once with a role (trigger, invoke or both), tested, saved, and reused by every integration that needs that system, through the connectivity agent when the system is on-premises.
