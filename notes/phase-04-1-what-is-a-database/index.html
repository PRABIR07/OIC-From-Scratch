What is a database?

Phase 4 · SQL & Databases, for complete beginners. You don’t need to know anything about databases to start. In this part we go slowly: what data is, where companies keep it, what a table looks like inside, and then you run your very first SQL query, word by word.

1What is data?

Your phone’s contact listOpen the contacts on your phone. For each person you’ve saved a name, a phone number, maybe an email and a birthday. Each of those small facts is a piece of data.

Data simply means facts that are written down so we can use them later. Nothing more scary than that.

At a shop

Bill number 4521 · 2 packets of rice · ₹180 · paid by UPI · 16 Oct 2026

At a school

Roll no 12 · Ananya · Class 8B · Maths 91 · Science 88

At a company

Employee 104 · Sneha Iyer · IT department · salary ₹85,000 · joined 1 June 2021

Notice something: in every example, the data is about a thing (a bill, a student, an employee), and it describes that thing with a few facts (number, name, amount, date). Keep this in mind. It’s the whole idea behind a database.

In one line: data = facts about things, written down so we can find and use them later.

2From register to Excel to database

How a growing company keeps its staff listWhen the company had 10 people, the office manager wrote them in a register. At 200 people, she moved to Excel. At 20,000 people across 5 cities, with HR, payroll and IT all needing the same list at the same time, Excel started breaking. That’s when companies move to a database.

So a database is a place where a company stores its data in an organised way, with rules, so that many people and many programs can read and change it safely at the same time.

You use databases every day without seeing them: your bank balance, your train ticket on IRCTC, your Swiggy order history, your college marks. Each of those apps asks a database for your data every time you open it.

3Why an OIC developer needs this

Remember: OIC’s job is to move data between applications. And behind almost every application, there’s a database. So sooner or later, OIC has to talk to one.

That’s why almost every OIC interview asks: “Can you write SQL?” By the end of Phase 4, your honest answer will be “yes”.

4Database, Oracle, SQL: three words, three jobs

The libraryA library has shelves full of books. It has a librarian who looks after the shelves and fetches books. And to ask the librarian for something, you speak a language you both understand. Three different things, working together.
WordIn the libraryIn plain words
DatabaseThe shelves full of booksThe organised collection of data itself
Oracle Database (a DBMS)The librarianThe software that stores the data, guards it and answers questions. Others: MySQL, SQL Server, PostgreSQL
SQLThe language you speak to the librarianThe language for asking a database questions and giving it instructions. Say it “S-Q-L” or “sequel”

DBMS means Database Management System: just the formal name for the “librarian” software. In this course we use Oracle Database, because OIC and Oracle Fusion live in Oracle’s world. The good news: about 90% of SQL is the same in every database, so what you learn here works almost everywhere.

5Inside a table

The school attendance registerThe first page of the register has printed headings across the top: Roll no · Name · Class. Then there’s one line for each student. A database keeps its data in exactly this shape, and calls it a table.
PartMeansIn DEPARTMENTS
TableA list of one kind of thingAll the departments
ColumnOne kind of fact, the same for every row. Goes down.LOCATION: the city of every department
RowOne thing, with all its facts. Goes across. Also called a record.30 · IT · Bengaluru
CellOne value, where a row and a column meetBengaluru

A database usually has many tables: one for employees, one for departments, one for salaries, one for leave… Each table holds one kind of thing. And the tables are connected to each other, which you’ll see in chapter 10.

Easy trick to remember: a column stands up like a column (pillar) in a building. A row lies flat like people sitting in a row in a cinema.

6The golden rules of a table

A table looks like an Excel sheet, but it follows strict rules. These rules are what make a database trustworthy.

✗ Allowed in Excel, not in a table
A cell with two values: Pune, Mumbai
Text in a number column: twenty thousand
Two rows for the same employee, by accident
Random notes typed under the data
Merged cells, colours that “mean something”
✓ The rule in a database
One value per cell
Every column has a type (number, text, date…)
Every row can be told apart (chapter 9)
Every row has the same columns
Meaning lives in data, not in colours

Why so strict? Because a program like OIC reads this data, not a human. A human can guess that “twenty thousand” means 20000. A program can’t. Strict rules mean every program gets clean, predictable data, every single time.

8Data types: what each column can hold

Kitchen containersMilk goes in a bottle. Rice goes in a jar. Eggs go in an egg tray. If you try to pour milk into the egg tray, it makes a mess. In a table, every column is a container of a fixed kind, called its data type. Put the wrong kind of value in, and the database refuses.

You only need three data types to start. Everything else is a variation of these.

KindOracle typeWhat it meansOur examples
✏️ TextVARCHAR2(30)Letters, numbers, symbols, up to 30 characters'Sneha', 'Bengaluru'
🔢 NumberNUMBER(10,2)A number: up to 10 digits in total, 2 of them after the decimal point85000, 85000.50
📅 DateDATEA calendar date (and a time of day)1 June 2021

How to read VARCHAR2(30) and NUMBER(10,2)

  • VARCHAR2 = “variable-length characters”, which just means text. The (30) is the maximum length. last_name VARCHAR2(30) can hold “Iyer” (4) or “Subramaniam” (11), but not a 40-letter name.
  • NUMBER(10,2): the first number (10) is the total digits, the second (2) is digits after the decimal point. So the biggest salary is 99,999,999.99. Plenty!
  • NUMBER(4): up to 4 digits, no decimals. Our dept_id is NUMBER(4), so it can be 10, 30 or 9999.

How you write each kind in SQL

KindWrite it likeWhy
Text'Pune' — in single quotesThe quotes tell Oracle “this is text, not a command”
Number85000 — no quotes, no commasCommas are for humans. 85,000 would confuse SQL
DateDATE '2021-06-01'Always year-month-day, so nobody mixes up 06/01 and 01/06

What happens if you put the wrong kind of value in

-- trying to save the word 'abc' in the salary column (a NUMBER)
ORA-01722: invalid number
-- newer Oracle versions word it more helpfully:
-- "unable to convert string value containing 'a' to a number"

Every Oracle error starts with ORA- and a number. Don’t be scared of them. They’re the database telling you exactly what went wrong. You’ll get very good at reading them.

9Primary key: a unique number for every row

Two Ravi Kumars in one classIn a class there are two students named Ravi Kumar. When the teacher says “Ravi Kumar, come here”, both stand up. So the school gives every student a roll number, and no two students ever share one. Roll number 12 always means exactly one student.

A primary key is a column whose value is different for every row, so it can point to exactly one row. In EMPLOYEES it’s emp_id. In DEPARTMENTS it’s dept_id.

Rule 1: unique

No two rows can have the same value. A second employee 101 is refused.

Rule 2: never empty

Every row must have one. An employee without an emp_id is refused.

Rule 3: never changes

Not enforced, but good practice. Your roll number doesn’t change when you change your hairstyle.

Why not use the name, or the email? Names repeat. Emails change when people marry or the company changes domain. A simple number that means nothing else is the safest key. In real systems you’ll see it called ID, PersonId, InvoiceId and so on. In Oracle Fusion, every record you touch from OIC has one.

10Foreign key: how tables are linked

The class number on your report cardYour report card says “Class 8B”. It doesn’t print the class teacher’s name, room number and timetable on every student’s card; it just says 8B. If you want those details, you look up 8B in the school’s class list. The “8B” on your card is a foreign key: a value that points to a row in another table.

So dept_id appears in two tables, with two different jobs:

WhereIts jobLike
DEPARTMENTS.dept_idPrimary key: names each departmentThe class list, where 8B is defined
EMPLOYEES.dept_idForeign key: points to a department“8B” written on your report card

Why not just write “IT, Bengaluru” on every employee?

Imagine IT moves from Bengaluru to Hyderabad. With the city copied onto 3,000 employee rows, you’d have to change 3,000 rows, and if you miss one, the data now disagrees with itself. With a foreign key, the city is stored once in DEPARTMENTS. Change that one cell, and every IT employee is instantly “in Hyderabad”.

And the foreign key has a rule: you can only point to something that exists. Try to give an employee department 99, which doesn’t exist, and the database refuses. That keeps the links honest. (Getting data from both tables together is called a join, and it gets its own part later in Phase 4.)

Bonus: manager_id in EMPLOYEES is also a foreign key, but it points back to EMPLOYEES itself, because a manager is also an employee. Sneha’s manager_id is 103: Amit.

11Rules that guard the data

The security guard at the gateA building guard checks everyone: “ID card? Visitor pass? No bags inside.” Anyone who breaks a rule doesn’t get in. A table has its own guards, called constraints. Every row is checked before it’s saved, and a row that breaks a rule is turned away with an error.
GuardRule, in plain wordsIn our tablesBreak it, and you get
PRIMARY KEYUnique and never empty (chapter 9)emp_id, dept_idORA-00001
FOREIGN KEYMust point to a row that exists (chapter 10)employees.dept_idORA-02291
NOT NULLThis box can’t be left emptylast_name, hire_dateORA-01400
UNIQUENo two rows can share this value (empty is allowed)email, dept_nameORA-00001
CHECKThe value must pass a testsalary > 0, status is ACTIVE or INACTIVEORA-02290
DEFAULTIf nobody gives a value, use this onestatus → ACTIVE(no error: it just fills the gap)

You don’t need to remember the error numbers today. Just remember the idea: the database protects itself. When OIC sends bad data (a missing name, a department that doesn’t exist), the database says no, and that “no” comes back to OIC as an error you can read and handle. You’ll learn to read these errors properly in Part 4.5.

12NULL: the empty box

The blank on a formA form has a box for “Email”. Karan left it blank. Does Karan have no email? Did he forget? Did he not want to share it? We simply don’t know. In a database, a box with nothing in it is called NULL, and it means “no value, unknown”.

In our company, NULL appears in two places: Karan’s email and Vikram’s department. Columns marked NOT NULL (like last_name) can never be NULL.

Why beginners must care about NULL: because “unknown” behaves strangely in questions. If you ask “whose email equals nothing?”, the database can’t say yes or no about an unknown value, so it returns nobody, even Karan, with no error. There’s a special way to ask about NULL, and you’ll learn it in Part 4.2. For now, just remember: NULL is not zero, not a space, but “unknown”.

One Oracle-only surprise: if you save an empty text '' (two quotes with nothing between), Oracle stores it as NULL. So in Oracle, “empty text” and “unknown” are the same thing.

13What is SQL?

SQL (Structured Query Language) is how you talk to the database. A “query” just means a question. The nice thing about SQL is that it reads almost like English:

SELECT first_name FROM employees WHERE dept_id = 30;
-- in English: "Show me the first names from the employees table, where the department is 30."

SQL has a small set of command words. They fall into five families, by what they do:

FamilyWhat it doesMain words
🔍 Ask (DQL)Reads data. Changes nothing.SELECT
✏️ Change (DML)Adds, edits or removes rowsINSERT, UPDATE, DELETE, MERGE
🏗️ Build (DDL)Creates or removes tables themselvesCREATE, ALTER, DROP
💾 Save / undo (TCL)Makes changes permanent, or cancels themCOMMIT, ROLLBACK
🔑 Permissions (DCL)Who is allowed to do whatGRANT, REVOKE

Here’s the good news: SELECT is used far more than all the others combined, and it’s completely safe: a SELECT only reads, so you can’t break anything with it. That’s why we start with SELECT, and spend the next two parts on it.

Three small grammar rules: ① Every statement ends with a semicolon ;, like a full stop. ② Command words like SELECT can be written in capitals or small letters; capitals are just a habit that makes them easy to spot. ③ Text values are case-sensitive: 'Pune' and 'PUNE' are different values.

When you make a mistake (you will, and that’s fine)

You typedOracle saysFix
SELECT * FROM department;ORA-00942: table or view … does not existThe table is departments, with an s
SELECT dept_nam FROM departments;ORA-00904: "DEPT_NAM": invalid identifierA column name is misspelled
SELECT dept_name location FROM departments;No error, but one column called LOCATION full of department names!A comma is missing between the two names

Read errors like a message from a friend: they nearly always say exactly what’s wrong. “Does not exist” means check the table name; “invalid identifier” means check the column name.

16Practice

Try each one yourself before opening the answer. All of them are also in phase4-1-first-look.sql.

1. Show every column of the employees table. How many rows come back?

SELECT * FROM employees; → 10 rows.

2. Show only the first name and job title of every employee.

SELECT first_name, job_title FROM employees; → 10 rows, 2 columns.

3. Show each employee’s first name and email. Find the one with an empty email.

SELECT first_name, email FROM employees; → Karan’s email shows as empty (NULL).

4. Show each employee’s first name and dept_id. Who has no department?

SELECT first_name, dept_id FROM employees; → Vikram.

5. Show emp_id, first name and manager_id. Who is Sneha’s manager?

SELECT emp_id, first_name, manager_id FROM employees; → Sneha’s manager_id is 103, which is Amit.

6. Break it on purpose: type SELECT * FROM staff;. What does Oracle say?

ORA-00942: the table doesn’t exist. There is no table called staff.

18Self-check

Answer in your head first, then tap to check.

1. In a table, does a column go across or down?

Down. A column is one kind of fact for every row; a row goes across.

2. What’s the difference between a database and Oracle Database?

The database is the data itself (the shelves); Oracle Database is the software that stores and serves it (the librarian).

3. Why can’t we use the employee’s name as the primary key?

Names can repeat (two Ravi Kumars), so a name can’t point to exactly one row.

4. EMPLOYEES has a dept_id column. Is it a primary key or a foreign key there?

A foreign key: it points to a row in DEPARTMENTS. In DEPARTMENTS, dept_id is the primary key.

5. Karan’s salary is 55000 and his email is NULL. What does NULL mean?

No value / unknown. It’s not zero and not a space.

6. How do you write the text Pune, the number 85000 and the date 1 June 2021 in SQL?

'Pune', 85000, DATE '2021-06-01'.

7. What does * mean in SELECT * FROM departments;?

Every column.

8. Can a SELECT change or delete your data?

No. SELECT only reads. Changing data uses INSERT, UPDATE, DELETE or MERGE.

All of it, in one sentence

A database is a strict, shared store of data, kept in tables of rows (things) and columns (facts) with fixed data types; a primary key names each row, a foreign key links tables, constraints guard the data, NULL means unknown, and you talk to it all in SQL, starting with SELECT … FROM …;
