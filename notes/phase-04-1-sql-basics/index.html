1Why databases matter in OIC

The office record roomEvery office has a record room: shelves of files, each file with a fixed form, and a clerk who fetches exactly the files you ask for. A database is that record room for software, and SQL (Structured Query Language) is the language you use to ask the clerk.

OIC moves data between applications, but behind most applications sits a database. As an OIC developer you’ll touch databases in four common ways:

The database you’ll meet most is Oracle Database, often as Oracle Autonomous Database (ATP) in the cloud. So all examples here use Oracle’s flavour of SQL. About 90% of it works the same in MySQL, SQL Server or PostgreSQL.

2Tables, rows and columns

A register with printed columnsAn attendance register has printed column headings (roll no, name, date) and one line per student. You can’t write a phone number in the “date” column, and every student gets a unique roll number. A table is a strict register like that: fixed columns, one row per thing.
SpreadsheetDatabaseThe difference
SheetTableHas a fixed structure decided in advance
Header rowColumnsEach has a data type (number, text, date) and rules
A lineRow (record)Must obey every rule, or it’s rejected
Anyone edits anythingTransactionsMany users at once, safely; changes are all-or-nothing (Part 4.2)
Thousands of linesMillions of rowsIndexes find one row instantly (Part 4.2)

A database holds many tables, grouped into schemas (one per user or application). Tables point at each other through keys (chapter 5), which is why it’s called a relational database.

3The five kinds of SQL statement

Every SQL statement belongs to one of five families. Knowing the family tells you what the statement can do and whether it can be undone.

FamilyStands for · doesStatementsIn this phase
DQLData Query: reads dataSELECTThis part (4.1)
DMLData Manipulation: changes rowsINSERT, UPDATE, DELETE, MERGEPart 4.2
DDLData Definition: builds structureCREATE, ALTER, DROP, TRUNCATEThe setup script; Part 4.2
TCLTransaction Control: saves or undoesCOMMIT, ROLLBACK, SAVEPOINTPart 4.2
DCLData Control: permissionsGRANT, REVOKEUsually your DBA’s job
Interview trap. DML can be undone with ROLLBACK until you COMMIT. DDL can’t: in Oracle, every DDL statement commits automatically, before and after it runs. That’s why TRUNCATE (DDL) can’t be rolled back, but DELETE (DML) can.

4Oracle data types

Containers in a kitchenYou keep milk in a bottle, rice in a jar and eggs in a tray. Pour milk into the egg tray and you have a mess. Every column has a data type: the shape of container it accepts.
TypeHoldsExample columnWatch out
VARCHAR2(50)Text, up to 50 bytesdept_nameLonger text is rejected (ORA-12899)
NUMBER(10,2)Numbers: 10 digits in total, 2 after the pointsalaryNUMBER(4) means whole numbers up to 9999
DATEDate and time, to the secondhire_dateAlways has a time part, even if it’s 00:00:00

Text values go in single quotes: 'Pune'. Numbers don’t: 30. Dates use a date literal: DATE '2026-10-16', always year-month-day, so there’s no confusion between 10 June and 6 October.

Oracle oddity: an empty string '' is treated as NULL (chapter 6). Other databases treat them as different things. If an integration sends "" for a name, Oracle stores NULL.

5Keys and constraints

Aadhaar numbers and family linksEvery person has a unique Aadhaar number, so two Ravi Kumars never get mixed up. A family register doesn’t copy your father’s whole record onto your page; it just writes his number. A primary key is the unique number; a foreign key is “his number, written on my page”.
ConstraintRuleBreaking it gives
PRIMARY KEYUnique and never empty; identifies the rowORA-00001: unique constraint … violated
FOREIGN KEYThe value must exist in the parent tableORA-02291: integrity constraint … violated - parent key not found
UNIQUENo two rows share the value (NULLs allowed)ORA-00001
NOT NULLA value is requiredORA-01400: cannot insert NULL into …
CHECKThe value must pass a test, like salary > 0ORA-02290: check constraint … violated
DEFAULTA value used when none is given (not really a rule)Nothing: it just fills the gap

Why should an integration developer care? Because when OIC inserts bad data, these errors are what come back as the fault. Read the constraint name in the message (EMP_DEPT_FK) and you know exactly which rule failed. That’s why good designers give constraints meaningful names.

6NULL: the unknown

The blank on a formA form’s “middle name” box is blank. Does the person have no middle name, or did they forget to write it? You can’t tell. NULL means “no value / unknown”. It is not zero, and not a space.

Because NULL is unknown, any comparison with NULL is unknown too, and WHERE only keeps rows where the condition is TRUE.

ExpressionResult
NULL = NULLunknown (not TRUE!)
NULL <> 5unknown
salary + NULLNULL
'Ravi' || NULL'Ravi' (Oracle)
email IS NULLTRUE or FALSE ✓

The only two correct tests

WHERE email IS NULL
WHERE email IS NOT NULL

WHERE email = NULL never matches any row, and gives no error. It’s a silent bug.

To replace a NULL with something readable, use NVL(email, 'no email') or the standard COALESCE(email, 'no email'). You’ll meet NULL traps again with NOT IN (chapter 9) and COUNT (Part 4.2).

Run Statement (Ctrl/⌘+Enter)

Runs the one statement where your cursor is, and shows a neat result grid. Use it for single queries.

Run Script (F5)

Runs everything in the editor, one after another, and shows text output. Use it for the setup script.

Messed something up? Just run the setup script again: it deletes and rebuilds everything. Oracle Live SQL (livesql.oracle.com) works the same way if you prefer it. Every statement ends with a semicolon ;. Keywords aren’t case-sensitive (select = SELECT), but text values are ('Pune' ≠ 'PUNE').

8SELECT, piece by piece

Ordering from the clerk“From the employees file, only IT, give me name and salary, highest salary first.” Every SELECT is that sentence, with each part in a fixed place.

All columns, all rows

SELECT * FROM departments;
DEPT_ID DEPT_NAME LOCATION
------- --------- ---------
     10 HR        Pune
     20 Finance   Mumbai
     30 IT        Bengaluru
     40 Sales     Delhi
     50 Legal     Chennai

Chosen columns, a calculation, and aliases

SELECT emp_id,
       first_name || ' ' || last_name AS full_name,     -- || joins text
       salary * 12                    AS annual_salary   -- maths works too
FROM   employees
WHERE  dept_id = 30
ORDER  BY emp_id;
EMP_ID FULL_NAME   ANNUAL_SALARY
------ ----------- -------------
   103 Amit Patel        1560000
   104 Sneha Iyer        1020000
   105 Arjun Singh        936000

AS gives a column a new name (an alias) in the result. With an alias like "Full Name" in double quotes you can use spaces and lowercase. SELECT * is fine for exploring, but in integrations always name the columns: if someone adds a column to the table, your integration’s output shape stays the same.

DUAL: a one-row table for quick calculations

SELECT 2 + 3 AS answer, UPPER('oic') AS shout FROM dual;
ANSWER SHOUT
------ -----
     5 OIC

9WHERE: choosing rows

The sievePour rice through a sieve and only the grains of the right size come out. WHERE is a sieve: each row is tested, and only rows where the condition is TRUE come through.
OperatorExampleKeeps rows where…
= <> < > <= >=salary >= 85000the comparison is true (<> and != both mean “not equal”)
BETWEEN … AND …salary BETWEEN 50000 AND 80000in the range, both ends included
IN (…)dept_id IN (10, 20)the value is in the list
LIKEfirst_name LIKE 'A%'the text matches a pattern
IS NULLemail IS NULLthere’s no value
AND OR NOTdept_id = 30 AND salary > 80000combinations

A range

SELECT emp_id, first_name, salary FROM employees
WHERE  salary BETWEEN 50000 AND 80000 ORDER BY emp_id;
EMP_ID FIRST_NAME SALARY
------ ---------- ------
   105 Arjun       78000
   106 Neha        60000
   107 Karan       55000
   109 Vikram      70000
   110 Anjali      52000

LIKE: two wildcards

% means “any number of characters (even none)”. _ means “exactly one character”.

SELECT first_name, last_name FROM employees
WHERE  last_name LIKE '_a%' ORDER BY emp_id;   -- second letter is a
FIRST_NAME LAST_NAME
---------- ---------
Amit       Patel
Vikram     Das
Anjali     Nair

AND before OR: the precedence trap

The NOT IN trap

SELECT emp_id, dept_id FROM employees
WHERE  dept_id NOT IN (10, 20) ORDER BY emp_id;
EMP_ID DEPT_ID
------ -------
   103      30
   104      30
   105      30
   107      40
   110      40       ← Vikram (109) has no department, but he's missing!

Vikram’s dept_id is NULL. “Is NULL not in (10, 20)?” is unknown, so the sieve drops him (chapter 6). If you want him, say so: WHERE dept_id NOT IN (10, 20) OR dept_id IS NULL.

10ORDER BY and DISTINCT

Without ORDER BY, the order of rows is not guaranteed. It may look sorted today and change tomorrow when the data grows. If order matters (paging, reports, files), always say it.

You writeMeans
ORDER BY salaryLowest first (ASC is the default)
ORDER BY salary DESCHighest first
ORDER BY dept_id, salary DESCBy department; inside each department, highest salary first
ORDER BY dept_id NULLS FIRSTPut empty values at the top. Oracle’s default puts NULLs last when ascending and first when descending.
ORDER BY annual_salaryYou may sort by a column alias

DISTINCT removes duplicate rows from the result

SELECT DISTINCT job_title FROM employees ORDER BY job_title;
JOB_TITLE
---------------------
Accountant
Consultant
Finance Manager
HR Executive
HR Manager
IT Manager
Integration Developer
Sales Executive      ← 10 employees, 8 different titles

Notice “IT Manager” comes before “Integration Developer”: sorting compares character by character, and capital T sorts before lowercase n. Text sorting follows the database’s character rules, not a dictionary.

11Paging with FETCH and OFFSET

The same photocopierRemember Part 3.4: APIs hand out data in pages with limit and offset. Databases do exactly the same. In fact, behind many REST APIs, this is the SQL that runs.

Page 1: the top 3 earners

SELECT first_name, salary
FROM   employees
ORDER  BY salary DESC
FETCH FIRST 3 ROWS ONLY;
FIRST_NAME SALARY
---------- ------
Amit       130000
Priya      120000
Ravi        95000

Page 2: skip 3, take 3

SELECT first_name, salary
FROM   employees
ORDER  BY salary DESC
OFFSET 3 ROWS FETCH NEXT 3 ROWS ONLY;
FIRST_NAME SALARY
---------- ------
Sneha       85000
Arjun       78000
Vikram      70000

Paging only makes sense with a stable ORDER BY. Sort by something unique (like emp_id) as a tie-breaker, or two rows with the same salary could swap between pages. Older Oracle code uses ROWNUM for this; FETCH FIRST (Oracle 12c and later) is the modern, readable way.

12Text and number functions

A single-row function takes a value from each row and returns a new value. It’s like the mapper functions in OIC, but run inside the database.

FunctionResultUsed for
UPPER('Ravi') · LOWER('Ravi')RAVI · raviCase-insensitive matching
INITCAP('ravi KUMAR')Ravi KumarCleaning names
'Ravi' || ' ' || 'Kumar'Ravi KumarJoining text
LENGTH('Pune')4Checking field sizes
SUBSTR('ravi.kumar@company.com', 1, 4)raviCutting text (start, length)
INSTR('ravi.kumar@company.com', '@')11Finding a position
TRIM(' HR ')HRRemoving spaces from file data
REPLACE('IT Dept', 'Dept', 'Team')IT TeamSwapping text
ROUND(97666.667, 2) · ROUND(97666.667)97666.67 · 97667Rounding
TRUNC(7.9)7Cutting off decimals
NVL(email, 'no email')the email, or no email if NULLFilling blanks
COALESCE(a, b, c)the first value that isn’t NULLFallbacks

Combine them: build a username from the email, and handle the missing one

SELECT emp_id,
       UPPER(last_name)                                      AS surname,
       NVL(SUBSTR(email, 1, INSTR(email, '@') - 1), 'no email') AS username
FROM   employees
WHERE  dept_id = 40 ORDER BY emp_id;
EMP_ID SURNAME USERNAME
------ ------- -----------
   107 MEHTA   no email
   110 NAIR    anjali.nair

Read nested functions from the inside out: find the @ (position 12 in anjali.nair@…), take everything before it, and if the result is NULL, say “no email”.

Case-insensitive search

SELECT first_name FROM employees WHERE UPPER(first_name) = 'RAVI';
FIRST_NAME
----------
Ravi      ← WHERE first_name = 'RAVI' would find nothing

13Dates and timestamps

One date, many spellings16/10/2026, 10/16/2026, 16-Oct-2026 and 2026-10-16 are the same day written four ways. The database stores the date itself; the spelling is chosen only when you show it or read it in. Most date bugs in integrations are spelling mistakes between two systems.
ExpressionResultDoes
SYSDATE · SYSTIMESTAMPnow (server time)Current date / timestamp
TO_CHAR(hire_date, 'DD-Mon-YYYY')01-Apr-2019Date → text
TO_CHAR(hire_date, 'DD/MM/YYYY')01/04/2019Date → text, another spelling
TO_DATE('16/10/2026', 'DD/MM/YYYY')the date 16 Oct 2026Text → date
DATE '2026-10-16' + 3015 Nov 2026Add days
DATE '2026-10-16' - DATE '2026-10-01'15Days between
ADD_MONTHS(DATE '2026-01-31', 1)28 Feb 2026Add months (handles month ends)
TRUNC(MONTHS_BETWEEN(DATE '2026-10-16', hire_date) / 12)completed yearsLength of service
TRUNC(SYSDATE)today at 00:00:00Drops the time part

Format codes you’ll use

YYYY year · MM month number · Mon / MON short month name · DD day · HH24 hour 0–23 · MI minutes (not MM!) · SS seconds · "T" literal text inside double quotes.

The ISO 8601 format that JSON and OIC use (Phase 2)

SELECT emp_id,
       TO_CHAR(last_update_date, 'YYYY-MM-DD"T"HH24:MI:SS') AS updated_iso
FROM   employees
WHERE  last_update_date > TIMESTAMP '2026-10-13 00:00:00'
ORDER  BY emp_id;
EMP_ID UPDATED_ISO
------ -------------------
   104 2026-10-14T09:30:00
   108 2026-10-15T11:00:00
   110 2026-10-13T18:00:00

Look at that WHERE clause: “everything changed since a point in time”. That’s the delta query from Part 3.4, in SQL. A scheduled OIC integration stores its last run time and asks exactly this.

Two classic date bugs. ① WHERE hire_date = DATE '2019-04-01' misses rows whose time isn’t exactly midnight. Use a range, or TRUNC(hire_date). ② Time zones: SYSDATE is the database server’s clock, which is often UTC in the cloud. 09:30 in India is 04:00 UTC. Agree on UTC between systems, and convert only for display.

14CASE: if-then inside a query

The exam grade90 and above is A, 70 and above is B, everything else is C. The teacher checks from the top and stops at the first rule that fits. CASE works the same way: the first true WHEN wins.
SELECT first_name, salary,
       CASE
         WHEN salary >= 100000 THEN 'Band A'
         WHEN salary >=  70000 THEN 'Band B'
         ELSE                       'Band C'
       END AS band
FROM   employees
ORDER  BY salary DESC
FETCH FIRST 6 ROWS ONLY;
FIRST_NAME SALARY BAND
---------- ------ ------
Amit       130000 Band A
Priya      120000 Band A
Ravi        95000 Band B
Sneha       85000 Band B
Arjun       78000 Band B
Vikram      70000 Band B

The short form: translating codes, like an OIC lookup

SELECT emp_id,
       CASE status WHEN 'ACTIVE' THEN 'A' WHEN 'INACTIVE' THEN 'I' ELSE '?' END AS status_code
FROM   employees WHERE emp_id IN (109, 110);
EMP_ID STATUS_CODE
------ -----------
   109 A
   110 I

Without an ELSE, unmatched rows get NULL. Older Oracle code uses DECODE(status, 'ACTIVE', 'A', 'INACTIVE', 'I', '?') for the short form; CASE is the standard and works in every database.

18Self-check

Answer in your head first, then tap to check.

1. What’s the difference between a primary key and a foreign key?

A primary key uniquely identifies each row in its own table. A foreign key stores another table’s primary key value, linking the two, and that value must exist in the parent table.

2. Which statement family is TRUNCATE, and why can’t it be rolled back?

DDL. In Oracle every DDL statement commits automatically.

3. Why does WHERE email = NULL return no rows?

Any comparison with NULL is unknown, not true, and WHERE only keeps true rows. Use IS NULL.

4. salary BETWEEN 50000 AND 80000: is a salary of exactly 80000 included?

Yes. BETWEEN includes both ends.

5. What do % and _ mean in LIKE?

% is any number of characters (even none); _ is exactly one character.

6. Write page 3 of employees by salary, 3 per page.

ORDER BY salary DESC, emp_id OFFSET 6 ROWS FETCH NEXT 3 ROWS ONLY.

7. Turn last_update_date into ISO 8601 text.

TO_CHAR(last_update_date, 'YYYY-MM-DD"T"HH24:MI:SS').

8. A CASE has no ELSE and no WHEN matches. What’s the result?

NULL.

9. What does an empty string '' become in Oracle?

NULL.

10. An insert fails with ORA-02291 … EMP_DEPT_FK … parent key not found. What’s wrong?

The dept_id you sent doesn’t exist in DEPARTMENTS. Fix the value or create the department first.

All of it, in one sentence

A database stores data in strict tables with typed columns, protected by keys and constraints; SELECT reads it with WHERE to choose rows (minding NULL), ORDER BY and FETCH to sort and page, and functions, dates and CASE to shape every value, exactly what OIC sends to the database for you.
