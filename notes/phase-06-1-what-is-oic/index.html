1The problem: applications don’t talk to each other

Priya’s first day at workPriya joins a company. HR adds her in the HR system. Now someone must also create her login in the IT system, add her to payroll so she gets a salary, and order a laptop in the asset system. Each system is a different application, from a different company. None of them know Priya exists, until someone tells them.

In many companies, that “someone” is a person. They copy Priya’s details from one screen and type them into the next. Four systems, four times the typing, four chances for a mistake. Now imagine 500 new joiners a month, plus people leaving, changing departments, getting promoted…

Integration means making applications pass data to each other automatically, with no human copying in between. HR adds Priya once, and the other three systems are updated within seconds, every time, without typos.

2Spaghetti vs a hub

Ten friends, one WhatsApp groupIf ten friends want to share plans by phoning each other one by one, they need 45 separate phone calls. Make one WhatsApp group, and everyone talks to one place. Applications have the same problem, and the same solution.
Point-to-point (spaghetti)A hub like OIC
BuildingCustom code for every pair of appsDrag-and-drop flows in one tool
When something failsSearch through many servers and logsOne screen shows every run, success or failure
When an app changesFix every link that touches itFix one connection
SecurityPasswords scattered in many programsCredentials kept in one guarded place

3So what is OIC?

Oracle Integration, usually called OIC (Oracle Integration Cloud), is Oracle’s cloud service for connecting applications. You build integrations: small automatic flows that take data from one place, change its shape if needed, and deliver it somewhere else.

Cloud

Oracle runs the servers, updates and backups. You just open it in a browser.

Low-code

You build flows by clicking and dragging, not by writing programs. (But you still need to understand data, which is why Phases 1–4 exist.)

Ready-made connectors

Hundreds of “adapters” already know how to talk to Oracle Fusion, Salesforce, SAP, databases, FTP servers, REST and SOAP APIs.

The industry name for this kind of product is iPaaS: integration Platform as a Service. Other iPaaS products you may hear about are MuleSoft, Boomi and Microsoft Logic Apps. They all solve the same problem; OIC is the natural choice for companies that run Oracle Fusion applications, which is a big part of the job market.

Version names: the current version is Oracle Integration 3 (sometimes written “OIC Gen 3”). The older one was “Generation 2”. New instances are always version 3, and every screen in these notes is from version 3. If you watch older YouTube videos, the screens will look different, but the ideas are the same.

4A day in the life of OIC

Before any theory, here are real things OIC does every day in companies. You’ll be able to build versions of all of them by the end of this course.

WhenWhat happensHow it starts
09:00A new joiner is added in Oracle HCM. OIC creates her login and laptop request.An event from the app (“a worker was created”)
11:30A sales website calls OIC: “What’s the stock for product 501?” OIC asks the ERP and replies in one second.An API call to OIC (REST)
14:00A supplier drops an invoice file on an SFTP server. OIC reads it and loads the invoices into Oracle ERP.A schedule that checks for files
23:00OIC collects the day’s orders from a database and sends a summary to the bank.A schedule (every night at 11 pm)

Look at the last column. Every integration needs something that starts it: an app saying “something happened”, someone calling it, or the clock. That starting point is called the trigger, and it’s the first of the eight words in the next chapter.

5The 8 words of OIC

A courier companyThink of OIC as a courier company. It has route plans for deliveries, vehicles that know how to reach certain places, address books with each customer’s location and gate pass, and a tracking page for every parcel. Each OIC word has a courier twin.
OIC wordCourier twinMeaning
IntegrationA delivery route planOne automatic flow: what starts it, what it does, where data goes
AdapterA type of vehicle (truck, boat, bike)Built-in know-how for talking to one kind of system: REST, SOAP, FTP, Oracle Fusion, a database…
ConnectionAn address-book entry: “Mumbai warehouse, gate pass #42”An adapter plus the details of one real system: its address (URL) and its login
TriggerThe pickup that starts a deliveryWhat starts an integration: a call, an event or a schedule
InvokeA drop-off on the routeA call from the integration out to another system
MapRepacking a parcel into the right boxChanging data from one shape into another (field to field)
ActivatePutting the route into serviceSwitching an integration ON so it can run
InstanceOne parcel’s journey, with a tracking numberOne single run of an integration, with its own ID and status

Read the table twice. Almost every sentence an OIC developer says uses these words: “The integration’s trigger is a REST connection, it maps the data and invokes the ERP adapter; after I activated it, the first instance failed.” In a few weeks, that sentence will sound completely normal to you.

6One integration, step by step

Let’s watch one simple integration from start to end. A mobile app asks OIC: “Give me employee 104’s details.” OIC gets them from the HR system and answers.

  1. 1
    TriggerThe app calls OIC’s address with GET /employees/104. This call starts a new instance.
  2. 2
    MapOIC rearranges the request into the shape the HR system expects. Maybe HR calls the field PersonNumber, not id.
  3. 3
    InvokeOIC calls the HR system’s API, using the HR connection (its URL and login).
  4. 4
    MapHR answers with 80 fields. The app needs only 4: name, email, department, manager. The map picks and renames them.
  5. 5
    ReplyOIC sends those 4 fields back to the app as JSON. The instance is marked Succeeded.

That’s it. Most integrations, even big ones, are just more of the same building blocks: a trigger, some maps, some invokes, plus a few actions for decisions and loops, which we’ll meet in Part 6.4.

7Where OIC lives: Oracle Cloud (OCI)

A flat in a big housing societyOracle’s cloud is like a huge housing society. Your company rents an account in it (a tenancy), divides it into wings (compartments) for different teams, and inside a wing you get your own flat: an OIC instance. Your integrations live inside that flat.
WordMeaning
OCIOracle Cloud Infrastructure: Oracle’s cloud, the “housing society”
TenancyYour company’s account in OCI
CompartmentA folder inside the tenancy, to keep teams or environments separate
RegionThe city where the data centre is, for example Mumbai or Hyderabad
OIC instanceYour own copy of OIC, with its own web address
Identity domainThe list of users and passwords that can log in (OCI IAM, which you met in Part 3.3)

Real projects almost always have two or three instances: Development (DEV) to build and test, sometimes Test (UAT) for business users to check, and Production (PROD) for the real thing. You build in DEV, then move the finished work to PROD. Never experiment in production!

One OIC instance contains several tools. As an OIC developer, you’ll spend 90% of your time in the first one.

FeatureWhat it’s forIn this course
⭐ IntegrationsBuilding, running and monitoring integration flowsPhases 6, 7, 8

B2BExchanging standard business documents (like EDI orders) with trading partnersMention only

Inside Integrations, your work is made of a few kinds of building blocks, and you’ll see these names on screen constantly: integrations, connections, lookups (code translation tables, like “M → Male”), libraries (small JavaScript functions) and projects (folders that keep one solution’s pieces together).

9Editions and billing, in simple words

EditionWhat you get
StandardIntegrations, standard adapters (REST, SOAP, FTP, databases, Oracle and many SaaS apps), recipes, File Server
EnterpriseEverything in Standard, plus enterprise adapters (SAP, E-Business Suite, JD Edwards, Siebel), Process Automation, B2B, robotic process automation and AI features
HealthcareEverything in Enterprise, plus healthcare message formats (HL7, FHIR)

How it’s paid for: OIC is billed in message packs. With a normal new licence, one pack covers 5,000 messages per hour. A small company might need 1 pack; a big one, 10 or more. You don’t pay per integration you build, but for the volume of traffic they handle. For a learning instance, 1 pack is plenty.

Why should a developer care about billing? Because design choices change the bill. An integration that checks a server every minute, all day, uses far more messages than one that runs once an hour. Good OIC developers think about volume.

10Who can do what: roles

The hospitalIn a hospital, the head of department can change anything, doctors treat patients, nurses monitor them, and visitors can only look. OIC gives each user a role in the same way, so people can only do what their job needs.
RoleCan doTypically given to
ServiceAdministratorEverything: settings, certificates, users’ work, all integrationsThe OIC admin
ServiceDeveloperBuild, edit, activate and test integrations and connectionsYou, the OIC developer
ServiceMonitorWatch runs, metrics and errors, without changing anythingSupport team
ServiceViewerLook at all pages and details, read-onlyAuditors, managers
ServiceUserBasic access, such as running integrations; can’t editBusiness users
ServiceInvokerOnly call integrations through their APIs; can’t open the screens at allOther applications (system users)

Remember ServiceInvoker. When another application needs to call your integration (like the mobile app in chapter 6), it gets its own user with only this role. That’s least privilege from Part 3.3 in action.

11Getting your own OIC

You can read and understand everything in Phase 6 without an instance. But to build, you need one. Here are the realistic options.

OptionHowGood to know
Your company’s DEV instanceAsk your manager or OIC admin for a user with the ServiceDeveloper roleBest option if you’re already on a project
Oracle Cloud free trialSign up at oracle.com/cloud/free, then create an Integration instance (steps below)The trial gives time-limited credits; OIC is not in the “Always Free” list, so it stops when credits or the trial end
Oracle LiveLabsSearch “Oracle Integration” on Oracle LiveLabs for guided workshopsSome workshops can run in a temporary sandbox; availability changes

Creating an instance in a trial account

  1. 1
    Open the Oracle Cloud ConsoleSign in, and choose your region (top bar) — for example India West (Mumbai).
  2. 2
    Find IntegrationOpen the ☰ menu → Developer Services → under Application Integration, click Integration.
  3. 3
    Pick a compartmentUse your own compartment, not root. Create one first if you don’t have it (Identity → Compartments).
  4. 4
    Create instanceClick Create instance and fill in: Name (e.g. learn-oic, it becomes part of the URL), Edition Standard (or Enterprise to see everything), Shape Development, License type “Subscribe to a new Oracle Integration license”, Message packs 1.
  5. 5
    WaitClick Create. After some minutes the State becomes Active.
  6. 6
    Open itClick the instance name, then Service console. OIC opens in a new tab. Bookmark it.
Save your credits. A running instance uses credits even when you’re not building. In a trial, you can Stop the instance from its OCI page when you finish for the day, and Start it again next time. And keep your trial password safe: the person who created the instance is its first administrator.

14Observability and Settings

The parcel tracking pageAfter you send a parcel, you open the courier’s tracking page: “Picked up · In transit · Delivered”, or “Delivery failed: address not found”. Observability is OIC’s tracking page for every run of every integration.
Observability itemShows
DashboardsThe big picture: how many runs succeeded or failed, system health
IntegrationsFor each active integration: messages received, processed, succeeded, errored
InstancesEvery single run, with its ID, status and your business identifier (like an employee number), so you can find “the run for employee 104”
ErrorsOnly the failed runs, with the reason, and buttons to resubmit some of them
Future runsA calendar of when scheduled integrations will run next
AgentsWhether your connectivity agents are up

Developers spend a surprising amount of time here. In interviews, “How do you troubleshoot a failed integration?” almost always starts with: “I open Observability → Instances, search by the business identifier, open the instance and read the activity stream.” You’ll do exactly that in Part 6.5.

Settings (mostly for the admin)

Certificates (to trust other systems’ HTTPS, Phase 1), Notifications (email settings), Tracing (how much detail runs record), Import and Export (moving work between instances), and File Server settings. As a developer you’ll mostly read these, not change them.

15How Phases 1–4 fit into OIC

Everything you learned before was preparation for this tool. Here’s exactly where each phase shows up on OIC’s screens.

You learnedYou’ll use it in OIC when…
Phase 1 · HTTPSetting a REST connection’s URL, choosing GET or POST, reading a 404 or 500 in a failed instance

That’s why people who skip the basics struggle in OIC: the clicking is easy, but understanding what you’re clicking needs Phases 1–4.

17Self-check

Answer in your head first, then tap to check.

1. In one line, what problem does OIC solve?

It makes applications pass data to each other automatically, instead of people copying it or every app being wired to every other app.

2. Why is a hub better than point-to-point?

Fewer links, one place to build and monitor, one place to fix when an app changes, and credentials kept in one place.

3. Adapter vs connection?

An adapter knows how to talk to a kind of system (like REST). A connection is an adapter plus one specific system’s URL and login.

4. Trigger vs invoke?

The trigger starts the integration (a call, an event or a schedule). An invoke is a call the integration makes out to another system.

5. What is an instance?

One single run of an integration, with its own ID and status.

6. Name the three statuses an integration moves through.

Draft, Configured, Active.

7. Which role should another application get if it only needs to call your integration?

ServiceInvoker.

8. Where do you go to find a failed run for employee 104?

Observability → Instances (or Errors), and search by the business identifier.

9. What does one message pack give you with a new licence?

5,000 messages per hour.

All of it, in one sentence

OIC is Oracle’s cloud hub for connecting applications: you build integrations that start from a trigger, map data and invoke other systems through connections built on adapters; you activate them, watch every instance in Observability, and it all lives in an OIC instance inside Oracle Cloud (OCI).
