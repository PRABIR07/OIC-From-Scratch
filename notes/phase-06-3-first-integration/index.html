Your first integration

Phase 6 · OIC Basics. Today you build a real, working integration: someone asks OIC for user number 1, OIC fetches that user from an API, and replies with just the details they need. First we understand each piece, then we build it together, click by click, with a “✓ You’ll see” check after every step.

1What we’ll build

The helpful receptionistA visitor asks the receptionist: “Can you tell me about employee number 1?” The receptionist phones the records office, which reads out a long file: name, username, email, full address, phone, website, company details. The receptionist doesn’t repeat all of it. She tells the visitor just the five things they need. Our integration is that receptionist.

JSONPlaceholder sends OIC this (long)

{
  "id": 1,
  "name": "Leanne Graham",
  "username": "Bret",
  "email": "Sincere@april.biz",
  "address": {
    "street": "Kulas Light",
    "city": "Gwenborough", …
  },
  "phone": "1-770-736-8031 x56442",
  "website": "hildegard.org",
  "company": {
    "name": "Romaguera-Crona", …
  }
}

OIC replies with this (just what’s needed)

{
  "userId": 1,
  "name": "Leanne Graham",
  "email": "Sincere@april.biz",
  "city": "Gwenborough",
  "company": "Romaguera-Crona"
}

Look at the right side carefully: the field names changed (id became userId), nested fields were flattened (address → city became just city), and everything else was dropped. That’s the heart of integration work, and the maps will do it.

2Three integration styles

When you create an integration, OIC first asks what starts it. That choice is the integration’s style, and it can’t be changed later.

StyleStarts when…Example
ApplicationAnother system calls it, or an app sends an eventA mobile app asks “give me user 1” (today’s integration)
ScheduleThe clock says so, or someone clicks “Submit now”Every night at 11 pm, copy the day’s orders (Part 6.6)
EventAnother OIC integration publishes a business event“Order created” is announced, and three integrations react (Phase 7)
A simple way to choose: Is a system or person calling it right now? → Application. Is it the clock? → Schedule. Is it another integration announcing something? → Event.

3The canvas: where you draw the flow

A whiteboard with a markerYou draw a flowchart on a whiteboard: a box, an arrow, the next box. The OIC canvas is that whiteboard. The flow runs from top to bottom, and you add steps by clicking the + on the line between two steps.
Part of the canvasWhat it does
The flow (middle)Your steps, top to bottom: trigger first, then maps, invokes and actions
The + on a lineHover over the line between two steps; a + appears. Click it to add an invoke or an action there
Side panelLists your trigger connections, invoke connections and actions
Toolbar (top)Business identifiers, layout (vertical/horizontal), validate, save, run test
Error iconA red icon while something is incomplete. Click it to see what’s missing. It’s normal while you’re still building

4The endpoint wizard: five questions

Filling in a courier booking formWhen you book a courier, the form asks: what’s this delivery called? To which address? Pickup or drop? What’s inside the parcel? What comes back? Every time you add a REST trigger or invoke, OIC opens a similar form, called the Adapter Endpoint Configuration Wizard, with a few pages of questions.
Wizard questionMeansToday, for the trigger
What do you want to call your endpoint?A name for this step on the canvasGetUser
What is the endpoint’s relative resource URI?The path, added after the base address (Phase 1: URLs)/users/{id}
What action do you want to perform?The HTTP method (Phase 1: GET, POST…)GET
Request parametersValues in the path {id} or after ? (Phase 3.1)id, a whole number
ResponseWhat shape of data comes backA sample JSON (chapter 5)

The {id} in curly brackets is a template parameter: a placeholder that’s filled in on each call. /users/1 means id = 1, /users/7 means id = 7. OIC spots the curly brackets and creates the id parameter for you.

The wizard ends with a Summary page; click Finish and the step appears on the canvas. You can reopen it any time to change answers.

5Why OIC needs a sample JSON

Showing the tailor an old shirtTo stitch a new shirt, the tailor asks you to bring an old one that fits. He doesn’t copy its colour, only its shape: sleeve length, collar, size. OIC is the same. Before any real data flows, it needs to know the shape of the data, so you paste one example JSON. OIC learns the field names and structure from it.
  • The sample only teaches the shape. The values in it (“Leanne Graham”) are never sent anywhere; real values arrive at runtime.
  • From the sample, OIC builds the tree of fields you’ll see in the mapper. If a field isn’t in the sample, it doesn’t exist for OIC, so include every field you need.
  • Use realistic values, not empty ones: "city": "Gwenborough" tells OIC it’s text; "city": "" or null tells it nothing.
  • Arrays need at least one item: [ { … } ], never an empty [].

This is why Phase 2 (JSON) mattered: if the sample isn’t valid JSON, the wizard refuses it. If you’re ever unsure, paste it into a JSON validator first.

6Maps and the mapper

Copying a form into another formYou have a filled-in college form and a blank job application. You copy across: “Name” → “Full name”, “Mobile” → “Contact number”, and skip the rest. A map is that copying, done by OIC on every run. The mapper is the screen where you draw the copy lines.
Mapper wordMeans
Sources (left)Everything available so far in this run: the trigger’s request, and responses of earlier invokes
Target (right)The message you’re building right now: the next invoke’s request, or the final reply
Drag and dropDrag a source field onto a target field to draw a line
ValidateChecks the map; success shows “…successfully validated”
Mapper functionsExtras like joining text or formatting dates (Phase 7)
Code viewShows the XSLT behind your lines, the language from Phase 2

OIC adds a map automatically before each invoke and before the final reply, so you just open it and draw the lines. Maps are saved as you go.

7Business identifiers: a label for every run

Writing a name on a parcelA courier office handles thousands of parcels. If a customer calls about “my parcel”, the staff search by the tracking number or name, not by checking every parcel. A business identifier is the label you put on every run, so you can find “the run for user 1” among thousands.

You choose up to three fields from the data as business identifiers, and one of them is the primary one. OIC records their values for every run, and shows them in Observability → Instances, where you can search by them. Today we use the user id. On real projects it’s an order number, employee number or invoice number: whatever support people will ask about.

Every integration needs a primary business identifier before it’s complete. Forgetting it is the most common reason a beginner’s integration won’t activate.

12Build · Part D: the two maps

Map 1: pass the id along

The caller sends an id to GetUser. FetchUser needs that same id to call JSONPlaceholder. Map 1 copies it across.

  1. 28
    Open Map 1Double-click (or click, then Edit) the map between GetUser and FetchUser.
    ✓ You’ll see: the mapper: Sources on the left, Target on the right.
  2. 29
    Find the source idIn Sources, expand GetUser Request (REST) and then Template Parameters. You’ll see id.
  3. 30
    Find the target idIn Target, expand FetchUser Request (REST) and then Template Parameters. You’ll see id.
  4. 31
    Draw the lineDrag the source id and drop it on the target id.
    ✓ You’ll see: a line joining them, and a mark on the target field showing it’s mapped.
  5. 32
    ValidateClick Validate.
    ✓ You’ll see: a message like “Map to FetchUser successfully validated.” Click Back (your map is saved).

  4. 36

15Common mistakes

What went wrongFix
Wrote /users/(id) or /users/idUse curly brackets: /users/{id}, so OIC creates the parameter
The sample JSON is refusedIt isn’t valid JSON: check commas, quotes and brackets (Phase 2)
A field is missing in the mapperIt wasn’t in the sample. Reopen the wizard (edit the trigger/invoke) and paste a complete sample
company shows the person’s nameYou mapped top-level name; map company → name instead
city is empty in the replyYou mapped address (the folder) instead of address → city
Can’t activate: error about identifiersAdd a primary business identifier (step 38)
Can’t edit the integrationIt’s Active. Deactivate first
Chose Schedule by mistakeThe style can’t change: create a new integration with style Application

17Self-check

Answer in your head first, then tap to check.

1. Which style for an integration that a mobile app calls?

Application.

2. Why do we paste a sample JSON?

To teach OIC the shape of the data (field names and structure). Its values are never sent.

3. What does {id} in /users/{id} mean?

A template parameter: a placeholder filled with a different value on each call.

4. In the mapper, which side is Sources and which is Target?

Sources (left) is where data comes from; Target (right) is the message being built.

5. Why does Map 1 exist?

To pass the id the caller sent (trigger request) into the id FetchUser needs (invoke request).

6. Why must we map company → name and not name?

Top-level name is the person’s name; company → name is the company’s name.

7. What is a business identifier for?

To label every run with a field (like the user id) so you can search for it in Observability.

8. You need to change an Active integration. What first?

Deactivate it.

All of it, in one sentence

An Application integration starts with a REST trigger (GET /users/{id}), uses maps to pass and reshape data, invokes another system through a connection, replies with only what’s needed, is labelled by a business identifier, and runs once you activate it.
